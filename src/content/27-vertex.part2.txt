@lesson
id: the-batch-tool
en: The batch tool
fa: ابزار دسته‌ای
url: https://academy.claude.com/courses/claude-with-google-cloud-s-vertex-ai

#explain
When Claude makes independent tool calls **one per turn**, every call costs a full round trip. The **batch tool** is a wrapper tool whose input is a list of other tool calls, so Claude can request several at once; your code runs them (in parallel if you like) and returns all results together.
~~
وقتی Claude فراخوانی‌های مستقل را **هر نوبت یکی** انجام می‌دهد، هر فراخوانی یک رفت‌وبرگشت کامل هزینه دارد. **ابزار دسته‌ای** یک ابزار پوششی است که ورودی‌اش فهرستی از فراخوانی‌های ابزارهای دیگر است؛ پس Claude می‌تواند چند تا را با هم درخواست کند؛ کد تو اجرایشان می‌کند (اگر خواستی موازی) و همهٔ نتیجه‌ها را با هم برمی‌گرداند.

#code python A batch tool in Messages API format
batch_tool_schema = {
    "name": "batch_tool",
    "description": "Invoke multiple other tool calls at once. Use it whenever you need "
                   "two or more independent tool calls.",
    "input_schema": {
        "type": "object",
        "properties": {"invocations": {"type": "array", "items": {
            "type": "object",
            "properties": {"name": {"type": "string"},
                           "arguments": {"type": "string", "description": "JSON-encoded arguments"}},
            "required": ["name", "arguments"]}}},
        "required": ["invocations"],
    },
}

def run_batch(invocations):
    return [{"tool": i["name"], "output": run_tool(i["name"], json.loads(i["arguments"]))}
            for i in invocations]
#end

#tip
Measure before adopting it: current Claude models already issue parallel tool calls on their own fairly often. If yours does, the plain approach is simpler.
~~
قبل از به کار بردنش اندازه بگیر: مدل‌های فعلی Claude همین حالا هم خیلی وقت‌ها خودشان ابزارها را موازی صدا می‌زنند. اگر مدل تو این کار را می‌کند، روش ساده‌تر بهتر است.

@lesson
id: tools-for-structured-data
en: Tools for structured data
fa: ابزار برای دادهٔ ساختاریافته
url: https://academy.claude.com/courses/claude-with-google-cloud-s-vertex-ai/tools-for-structured-data

#explain
Compared with prompt-based methods (prefill and stop sequences), the **tool-based** approach is more reliable: define a tool whose JSON schema *is* the structure you want, have Claude call it, and read the tool's input as your data. The course forces the call with `tool_choice={"type": "tool", "name": ...}`; it's more setup, but the output is far more consistent.

**Today:** on the newest models (Opus 5.5, Sonnet 5.5, Fable 5.1) forced `tool_choice` returns a 400. Use **structured outputs** (supported on Vertex) for pure extraction, or `auto` + `strict: true` + an explicit instruction when you really want a tool call.
~~
در مقایسه با روش‌های مبتنی بر پرامپت (پیش‌پر کردن و دنبالهٔ توقف)، روش **مبتنی بر ابزار** مطمئن‌تر است: ابزاری تعریف کن که اسکیمای JSON آن *همان* ساختاری است که می‌خواهی، کاری کن Claude صدایش بزند و ورودی ابزار را به‌عنوان داده‌ات بخوان. دوره فراخوانی را با `tool_choice={"type": "tool", "name": ...}` اجباری می‌کند؛ راه‌اندازی بیشتری می‌خواهد، ولی خروجی خیلی یکدست‌تر است.

**امروز:** روی جدیدترین مدل‌ها (Opus 5.5، Sonnet 5.5، Fable 5.1) اجبار `tool_choice` خطای 400 می‌دهد. برای استخراج خالص از **خروجی ساختاریافته** (که Vertex پشتیبانی می‌کند) استفاده کن، یا وقتی واقعاً فراخوانی ابزار می‌خواهی، `auto` + `strict: true` + یک دستور صریح.

#code python Structured extraction on a current model
r = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=2000,
    output_config={"format": {"type": "json_schema", "schema": {
        "type": "object",
        "properties": {"title": {"type": "string"}, "author": {"type": "string"},
                       "key_insights": {"type": "array", "items": {"type": "string"}}},
        "required": ["title", "author", "key_insights"],
        "additionalProperties": False}}},
    messages=[{"role": "user", "content": f"<article>{article}</article>\nExtract the summary data."}],
)
data = json.loads(next(b.text for b in r.content if b.type == "text"))
#end

#analogy
Prompt-based extraction is asking someone to **write their details neatly on a blank page**; tool-based is handing them a **printed form**; structured outputs is a form where the pen **can't write outside the boxes**.
~~
استخراج مبتنی بر پرامپت مثل این است که از کسی بخواهی **مشخصاتش را تمیز روی یک برگهٔ سفید بنویسد**؛ مبتنی بر ابزار مثل دادن **یک فرم چاپی** است؛ خروجی ساختاریافته فرمی است که قلم **اصلاً نمی‌تواند بیرون خانه‌ها بنویسد**.

id: reranking-results
en: Reranking results
fa: رتبه‌بندی دوبارهٔ نتیجه‌ها

#explain
Retrieve extra candidates (say 10), then ask Claude to **reorder them by relevance** to the question and keep the best few. One more call, often much better context for the final answer.
~~
کاندیداهای بیشتری بازیابی کن (مثلاً ۱۰ تا)، بعد از Claude بخواه آن‌ها را **بر اساس ارتباط** با سؤال دوباره مرتب کند و چند تای بهتر را نگه دار. یک فراخوانی بیشتر، و اغلب زمینهٔ خیلی بهتر برای جواب نهایی.

#code python Rerank with structured outputs
from pydantic import BaseModel

class Ranking(BaseModel):
    doc_ids: list[int]        # most relevant first

def rerank(question, candidates, k=3):
    docs = "\n".join(f'<doc id="{i}">{c}</doc>' for i, c in enumerate(candidates))
    r = client.messages.parse(
        model="claude-haiku-5-5", max_tokens=500,
        messages=[{"role": "user", "content":
            f"<question>{question}</question>\n<documents>\n{docs}\n</documents>\n"
            f"Rank the {k} documents most relevant to the question."}],
        output_format=Ranking,
    )
    return [candidates[i] for i in r.parsed_output.doc_ids[:k] if 0 <= i < len(candidates)]
#end

#analogy
The search engine picks the **shortlist**; Claude is the **hiring manager** who orders the final candidates.
~~
موتور جست‌وجو **فهرست کوتاه** را انتخاب می‌کند؛ Claude **مدیر استخدامی** است که کاندیداهای نهایی را مرتب می‌کند.

@lesson
id: contextual-retrieval
en: Contextual retrieval
fa: بازیابی زمینه‌دار
url: https://academy.claude.com/courses/claude-with-google-cloud-s-vertex-ai

#explain
Before indexing, ask Claude to write a **short context sentence** for each chunk based on the whole document ("This chunk is from ACME's Q2 2026 report, discussing revenue"), and index chunk + context. Lost context is restored, so both semantic and BM25 search find the right chunks more often.
~~
قبل از نمایه‌سازی، از Claude بخواه بر اساس کل سند برای هر تکه یک **جملهٔ زمینهٔ کوتاه** بنویسد («این تکه از گزارش فصل دوم ۲۰۲۶ شرکت ACME است و دربارهٔ درآمد حرف می‌زند») و تکه + زمینه را نمایه کن. زمینهٔ گم‌شده برمی‌گردد؛ پس هم جست‌وجوی معنایی و هم BM25 بیشتر وقت‌ها تکه‌های درست را پیدا می‌کنند.

#code python Cache the document, contextualize every chunk
def contextualize(document, chunk):
    r = client.messages.create(
        model="claude-haiku-5-5", max_tokens=150,
        system=[{"type": "text", "text": f"<document>{document}</document>",
                 "cache_control": {"type": "ephemeral"}}],          # same for every chunk
        messages=[{"role": "user", "content":
            f"<chunk>{chunk}</chunk>\nWrite one short sentence situating this chunk within "
            "the document, to improve search retrieval. Reply with the sentence only."}],
    )
    return "".join(b.text for b in r.content if b.type == "text") + "\n" + chunk
#end

#tip

@cheatsheet
- Enable Claude in **Model Garden**; authenticate with `gcloud auth application-default login` (a service account in production).
- `pip install "anthropic[vertex]"` → `AnthropicVertex(project_id=..., region="global")` → same `messages.create` as the API course.
- Copy model IDs from Model Garden (older models may have an `@date` suffix).
- Output control: prefill + stop sequences on older models; structured outputs on the newest.
- Tools: same format as the API course; **batch tool** for many independent calls; **tools for structured data** (or structured outputs today).
- RAG extras: **reranking**, **contextual retrieval** (cache the document while contextualizing).
- Not on Vertex: code execution, Files API, web fetch, MCP connector; web search is the basic version only.
- Claude Code on Vertex: `CLAUDE_CODE_USE_VERTEX=1` + region + project ID.
~~
- Claude را در **Model Garden** فعال کن؛ با `gcloud auth application-default login` احراز هویت کن (در محیط واقعی با یک حساب سرویس).
- `pip install "anthropic[vertex]"` ← `AnthropicVertex(project_id=..., region="global")` ← همان `messages.create` دورهٔ API.
- شناسهٔ مدل‌ها را از Model Garden کپی کن (مدل‌های قدیمی‌تر ممکن است پسوند `@تاریخ` داشته باشند).
- کنترل خروجی: پیش‌پر کردن + دنبالهٔ توقف روی مدل‌های قدیمی‌تر؛ خروجی ساختاریافته روی جدیدترین‌ها.
- ابزارها: همان قالب دورهٔ API؛ **ابزار دسته‌ای** برای فراخوانی‌های مستقل زیاد؛ **ابزار برای دادهٔ ساختاریافته** (یا امروزه خروجی ساختاریافته).
- چیزهای اضافهٔ RAG: **رتبه‌بندی دوباره**، **بازیابی زمینه‌دار** (موقع زمینه‌دار کردن، سند را کش کن).
- روی Vertex نیست: اجرای کد، Files API، web fetch، MCP connector؛ جست‌وجوی وب فقط نسخهٔ پایه.
- Claude Code روی Vertex: `CLAUDE_CODE_USE_VERTEX=1` + منطقه + شناسهٔ پروژه.

A: Put the whole document in a cached block and use a fast model, so each chunk's request mostly reads from the cache. || کل سند را در یک بلوک کش‌شده بگذار و از یک مدل سریع استفاده کن تا درخواست هر تکه بیشترش از کش خوانده شود.
