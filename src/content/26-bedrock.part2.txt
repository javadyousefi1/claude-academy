id: tool-schemas

fa: اسکیمای ابزارها (قالب Converse)

#explain
The schema content is the same (name, a good description, JSON Schema for inputs), but Converse wraps it differently: each tool is a `toolSpec`, and the schema goes under `inputSchema.json`.
~~
محتوای اسکیما همان است (اسم، یک توضیح خوب، اسکیمای JSON برای ورودی‌ها)، ولی Converse آن را متفاوت بسته‌بندی می‌کند: هر ابزار یک `toolSpec` است و اسکیما زیر `inputSchema.json` می‌آید.

#code python A Converse tool definition
get_current_datetime_tool = {
    "toolSpec": {
        "name": "get_current_datetime",
        "description": "Returns the current date and time. Call this for any relative date "
                       "like 'today' or 'in 3 weeks'.",
        "inputSchema": {"json": {
            "type": "object",
            "properties": {"date_format": {"type": "string",
                                           "description": "Python strftime format"}},
            "required": ["date_format"],
        }},
    }
}
tool_config = {"tools": [get_current_datetime_tool]}
#end

#analogy
Same menu description, different **menu holder**: Anthropic's API and Bedrock just print it in different frames.

همان توضیح منو، با **جامنوی** متفاوت: API آنتروپیک و Bedrock فقط آن را در قاب‌های متفاوت چاپ می‌کنند.

@lesson
id: sending-tool-results
en: Sending tool results
fa: فرستادن نتیجهٔ ابزار
url: https://academy.claude.com/courses/claude-with-amazon-bedrock

#explain
Answer with a **user** message containing one `toolResult` per `toolUse`, matched by `toolUseId`. Content can be text or JSON; add `"status": "error"` when the tool failed so Claude can recover.
~~
با یک پیام **کاربر** جواب بده که برای هر `toolUse` یک `toolResult` دارد و با `toolUseId` جفت می‌شود. محتوا می‌تواند متن یا JSON باشد؛ وقتی ابزار شکست خورد `"status": "error"` اضافه کن تا Claude بتواند جبران کند.

#code python Building toolResult blocks
results = []
for block in assistant_message["content"]:
    if "toolUse" in block:
        tu = block["toolUse"]
        try:
            output = run_tool(tu["name"], tu["input"])
            results.append({"toolResult": {"toolUseId": tu["toolUseId"],
                                           "content": [{"text": str(output)}]}})
        except Exception as e:
            results.append({"toolResult": {"toolUseId": tu["toolUseId"],
                                           "content": [{"text": f"Error: {e}"}],
                                           "status": "error"}})
messages.append({"role": "user", "content": results})
#end

@lesson
id: batch-tool-use
en: Batch tool use
fa: استفادهٔ دسته‌ای از ابزار
url: https://academy.claude.com/courses/claude-with-amazon-bedrock

#explain
Sometimes Claude calls tools **one at a time** even when they're independent, which means extra round trips. The **batch tool** pattern adds one more tool, `batch_tool`, whose input is a **list of other tool calls**. Claude can then request several operations at once, and your code runs them all (even in parallel) and returns the combined results. Current models do parallel tool calls on their own more often, but the pattern is still handy when you want to encourage it.
~~
گاهی Claude ابزارها را **یکی‌یکی** صدا می‌زند، حتی وقتی مستقل‌اند؛ یعنی رفت‌وبرگشت‌های اضافه. الگوی **ابزار دسته‌ای** یک ابزار دیگر به اسم `batch_tool` اضافه می‌کند که ورودی‌اش **فهرستی از فراخوانی‌های ابزارهای دیگر** است. آن وقت Claude می‌تواند چند عملیات را با هم درخواست کند و کد تو همه را اجرا می‌کند (حتی موازی) و نتیجه‌های ترکیبی را برمی‌گرداند. مدل‌های فعلی بیشتر وقت‌ها خودشان ابزارها را موازی صدا می‌زنند، ولی این الگو وقتی می‌خواهی تشویقش کنی هنوز به درد می‌خورد.

#code python The batch tool
batch_tool = {"toolSpec": {
    "name": "batch_tool",
    "description": "Invoke several other tools at once. Use it whenever you need two or "
                   "more independent tool calls.",
    "inputSchema": {"json": {
        "type": "object",
        "properties": {"invocations": {"type": "array", "items": {
            "type": "object",
            "properties": {"name": {"type": "string"},
                           "arguments": {"type": "string", "description": "JSON-encoded arguments"}},
            "required": ["name", "arguments"]}}},
        "required": ["invocations"],
    }},
}}

def run_batch(invocations):
    return [{"tool": i["name"], "output": run_tool(i["name"], json.loads(i["arguments"]))}
            for i in invocations]
#end

#analogy
Like giving a waiter **one order slip with the whole table's dishes** instead of calling them back for each plate.
~~
مثل این است که به گارسون **یک برگهٔ سفارش با غذای همهٔ سر میز** بدهی، به جای این‌که برای هر بشقاب دوباره صدایش کنی.

@lesson
id: structured-data-with-tools
en: Structured data with tools
fa: دادهٔ ساختاریافته با ابزارها
url: https://academy.claude.com/courses/claude-with-amazon-bedrock

#explain
A reliable way to get structured data: define a tool whose **input schema is exactly the data shape you want** (for example `article_summary` with `title`, `author`, `key_insights`), then make Claude call it. You never run the tool; you just **read its input**, which is your structured data. The course forces the call with `toolChoice={"tool": {"name": ...}}`.

**Note:** on the newest models, forcing a specific tool may be rejected; use **structured outputs** instead, or `auto` with a clear instruction, and check that the call arrived.
~~
یک راه مطمئن برای گرفتن دادهٔ ساختاریافته: ابزاری تعریف کن که **اسکیمای ورودی‌اش دقیقاً شکل داده‌ای است که می‌خواهی** (مثلاً `article_summary` با `title`، `author`، `key_insights`)، بعد کاری کن Claude صدایش بزند. هیچ‌وقت ابزار را اجرا نمی‌کنی؛ فقط **ورودی‌اش را می‌خوانی** که همان دادهٔ ساختاریافتهٔ توست. دوره فراخوانی را با `toolChoice={"tool": {"name": ...}}` اجباری می‌کند.

**توجه:** روی جدیدترین مدل‌ها اجبار به یک ابزار مشخص ممکن است رد شود؛ به جایش از **خروجی ساختاریافته** استفاده کن، یا `auto` با یک دستور روشن، و چک کن فراخوانی رسیده باشد.

#code python The tool-as-schema trick
summary_tool = {"toolSpec": {
    "name": "article_summary",
    "description": "Record a structured summary of the article.",
    "inputSchema": {"json": {"type": "object", "properties": {
        "title": {"type": "string"}, "author": {"type": "string"},
        "key_insights": {"type": "array", "items": {"type": "string"}}},
        "required": ["title", "author", "key_insights"]}},
}}
response = client.converse(
    modelId=MODEL_ID,
    messages=[{"role": "user", "content": [{"text": f"<article>{article}</article>\nSummarize it."}]}],
    toolConfig={"tools": [summary_tool], "toolChoice": {"tool": {"name": "article_summary"}}},
    inferenceConfig={"maxTokens": 1000},
)
data = next(b["toolUse"]["input"] for b in response["output"]["message"]["content"] if "toolUse" in b)
#end

#analogy
It's like handing someone a **form with labeled boxes** and saying "fill this in": the form's shape *is* the answer's shape.
~~
مثل این است که **فرمی با خانه‌های برچسب‌دار** دست کسی بدهی و بگویی «این را پر کن»: شکل فرم *همان* شکل جواب است.

@lesson
id: reranking-results
en: Reranking results
fa: رتبه‌بندی دوبارهٔ نتیجه‌ها
url: https://academy.claude.com/courses/claude-with-amazon-bedrock

#explain
Hybrid search finds good **candidates**, but its order isn't always the best for the actual question. **Reranking** adds one step: retrieve more candidates than you need (say 10), then ask Claude to **reorder them by relevance** to the question and keep the top 3. It costs one extra call but often improves answer quality noticeably, especially for subtle questions.
~~
جست‌وجوی ترکیبی **کاندیداهای** خوبی پیدا می‌کند، ولی ترتیبش همیشه برای سؤال واقعی بهترین نیست. **رتبه‌بندی دوباره** یک قدم اضافه می‌کند: بیشتر از نیازت کاندیدا بازیابی کن (مثلاً ۱۰ تا)، بعد از Claude بخواه آن‌ها را **بر اساس ارتباط** با سؤال دوباره مرتب کند و ۳ تای برتر را نگه دار. یک فراخوانی اضافه هزینه دارد، ولی اغلب کیفیت جواب را محسوس بهتر می‌کند، مخصوصاً برای سؤال‌های ظریف.

#code python Rerank with Claude
def rerank(question, candidates, k=3):
    listing = "\n".join(f'<doc id="{i}">{c}</doc>' for i, c in enumerate(candidates))
    prompt = (f"<question>{question}</question>\n<documents>\n{listing}\n</documents>\n"
              f"Return the ids of the {k} most relevant documents, most relevant first, "
              f"as a comma-separated list of numbers and nothing else.")
    response = client.converse(modelId=MODEL_ID,
                               messages=[{"role": "user", "content": [{"text": prompt}]}],
                               inferenceConfig={"maxTokens": 50})
    ids = response["output"]["message"]["content"][0]["text"].split(",")
    return [candidates[int(i)] for i in ids if i.strip().isdigit()][:k]
#end

#analogy
Search is the **first audition round** that picks 10 singers; reranking is the **judges' final ranking** of those 10.
~~
جست‌وجو **دور اول تست خوانندگی** است که ۱۰ خواننده را انتخاب می‌کند؛ رتبه‌بندی دوباره **رتبه‌بندی نهایی داورها** بین همان ۱۰ نفر است.

@lesson
id: contextual-retrieval
en: Contextual retrieval
fa: بازیابی زمینه‌دار
url: https://academy.claude.com/courses/claude-with-amazon-bedrock/contextual-retrieval

#explain
A chunk cut out of a long document often **loses its context**: "Revenue grew 3% over the previous quarter" (which company? which quarter?). **Contextual retrieval** fixes this at indexing time: for each chunk, ask Claude to write a short **context sentence** based on the whole document, prepend it to the chunk, and index the combined text (for both embeddings and BM25). Searches now match on that context too.
~~
تکه‌ای که از یک سند طولانی بریده می‌شود اغلب **زمینه‌اش را از دست می‌دهد**: «درآمد نسبت به فصل قبل ۳٪ رشد کرد» (کدام شرکت؟ کدام فصل؟). **بازیابی زمینه‌دار** این را موقع نمایه‌سازی درست می‌کند: برای هر تکه از Claude بخواه بر اساس کل سند یک **جملهٔ زمینه** کوتاه بنویسد، آن را به اول تکه بچسبان و متن ترکیبی را نمایه کن (هم برای embedding و هم برای BM25). حالا جست‌وجوها روی همان زمینه هم تطبیق پیدا می‌کنند.

#code python Add context to each chunk before indexing
def contextualize(document, chunk):
    prompt = (f"<document>{document}</document>\n"
              f"Here is a chunk from the document:\n<chunk>{chunk}</chunk>\n"
              "Write one short sentence situating this chunk within the overall document "
              "to improve search retrieval. Answer with the sentence only.")
    r = client.converse(modelId=MODEL_ID,
                        messages=[{"role": "user", "content": [{"text": prompt}]}],
                        inferenceConfig={"maxTokens": 100})
    return r["output"]["message"]["content"][0]["text"] + "\n" + chunk

indexed_chunks = [contextualize(report_text, c) for c in chunks]
#end

#tip
**Cool tip:** the whole document is the same for every chunk, so put it in a **cached** block (Converse uses a `cachePoint` block, covered below). You then pay full price for the document once, and a fraction for every other chunk.
~~
**نکتهٔ خفن:** کل سند برای همهٔ تکه‌ها یکی است؛ پس آن را در یک بلوک **کش‌شده** بگذار (Converse از بلوک `cachePoint` استفاده می‌کند که در ادامه می‌آید). آن وقت قیمت کامل سند را فقط یک بار می‌دهی و برای بقیهٔ تکه‌ها بخش کوچکی از آن را.

#analogy

~~

#explain

#code python A cached system prompt in Converse

    modelId=MODEL_ID,
    system=[
        {"text": LONG_STYLE_GUIDE},          # thousands of stable tokens

    ],
    messages=[{"role": "user", "content": [{"text": "Rewrite this headline in our style: ..."}]}],
    inferenceConfig={"maxTokens": 300},

**Computer use** lets Claude operate a desktop environment: take screenshots, move the mouse, click, type. It's useful for tasks without an API, like **automated QA testing** of a web app ("sign up, add an item to the cart, check the total") or legacy software. It's slower and less precise than APIs, so use it where nothing better exists, and always in an **isolated virtual machine or container**.
~~
**استفاده از کامپیوتر** به Claude اجازه می‌دهد یک محیط دسکتاپ را بچرخاند: اسکرین‌شات بگیرد، ماوس را حرکت دهد، کلیک کند، تایپ کند. برای کارهایی که API ندارند مفید است، مثل **آزمون خودکار کیفیت (QA)** یک وب‌اپ («ثبت‌نام کن، یک کالا به سبد اضافه کن، جمع را چک کن») یا نرم‌افزارهای قدیمی. از APIها کندتر و کم‌دقت‌تر است؛ پس جایی به کارش ببر که گزینهٔ بهتری نیست، و همیشه در یک **ماشین مجازی یا کانتینر ایزوله**.

#warn
Treat everything on screen as untrusted: a web page could contain text that tries to give Claude instructions. Don't give the environment access to sensitive accounts, and require confirmation for consequential actions.
~~
هر چیزی را که روی صفحه است غیرقابل‌اعتماد حساب کن: یک صفحهٔ وب ممکن است متنی داشته باشد که سعی کند به Claude دستور بدهد. به آن محیط دسترسی به حساب‌های حساس نده و برای کارهای پیامددار تأیید بخواه.

#analogy
Computer use is a **remote helper looking at your screen through a video call**: capable, but you don't let them near your bank account.

#explain
Under the hood it's the **same tool-use loop** you built earlier. You declare Anthropic's computer-use tool (with the screen size); Claude returns `tool_use` actions like "screenshot", "left_click at (x, y)" or "type 'hello'"; **your code** performs them in the virtual desktop and returns a **screenshot** as the tool result; Claude looks at it and decides the next action. Anthropic provides a reference implementation (a Docker container with a desktop) to start from.
~~
در باطن همان **حلقهٔ استفاده از ابزار** است که قبلاً ساختی. ابزار computer use آنتروپیک را (با اندازهٔ صفحه) اعلام می‌کنی؛ Claude کارهایی مثل «اسکرین‌شات»، «کلیک چپ روی (x, y)» یا «تایپ 'hello'» را به شکل `tool_use` برمی‌گرداند؛ **کد تو** آن‌ها را در دسکتاپ مجازی انجام می‌دهد و یک **اسکرین‌شات** را به‌عنوان نتیجهٔ ابزار برمی‌گرداند؛ Claude نگاهش می‌کند و کار بعدی را تصمیم می‌گیرد. Anthropic یک پیاده‌سازی مرجع (یک کانتینر Docker با دسکتاپ) برای شروع ارائه می‌دهد.

#steps
1. Declare the computer-use tool with the display size.
2. Claude asks for an action (e.g., take a screenshot).
3. Your code performs it in the VM.
4. Return a fresh screenshot as the tool result.
5. Repeat until the task is done.
~~
1. ابزار computer use را با اندازهٔ صفحه اعلام کن.
2. Claude یک کار می‌خواهد (مثلاً گرفتن اسکرین‌شات).
3. کد تو آن را در ماشین مجازی انجام می‌دهد.
4. یک اسکرین‌شات تازه را به‌عنوان نتیجهٔ ابزار برگردان.
5. تا تمام شدن کار تکرار کن.

#tip
Computer use is still versioned and evolving: the newest models use a newer computer **toolset** declaration on some platforms (Bedrock still accepts the earlier version for some models). Copy the declaration from the current docs, not from old blog posts.
~~
استفاده از کامپیوتر هنوز نسخه‌دار و در حال تکامل است: جدیدترین مدل‌ها روی بعضی سکوها از اعلان تازه‌تری به اسم **toolset** استفاده می‌کنند (Bedrock هنوز نسخهٔ قبلی را برای بعضی مدل‌ها می‌پذیرد). اعلان را از مستندات فعلی کپی کن، نه از پست‌های قدیمی وبلاگ‌ها.

@cheatsheet
- No Anthropic key: **IAM + AWS credentials**; enable **model access** per region.
- `boto3.client("bedrock-runtime").converse(modelId=..., messages=[{"role": "user", "content": [{"text": ...}]}])`.
- **Inference profiles** (`us.` / `global.` prefixes) route to regions with capacity.
- Streaming: `converse_stream` → `contentBlockDelta` events.
- Tools: `toolConfig={"tools": [{"toolSpec": ...}]}` → `toolUse` → `toolResult` (same `toolUseId`).
- Structured data: tool-as-schema, or structured outputs on newer models.
- RAG extras: **reranking** with Claude, **contextual retrieval** (context sentence per chunk).
- Caching: `{"cachePoint": {"type": "default"}}` after the stable part.
- Not on Bedrock: Anthropic server tools (web search, code execution), Files API, Message Batches.
- Newest models/features: Anthropic SDK `AnthropicBedrockMantle` with `anthropic.`-prefixed model IDs.
- Claude Code: `CLAUDE_CODE_USE_BEDROCK=1`; parallelize with **git worktrees**.
~~

Q: Why add a context sentence to each chunk before indexing? || چرا قبل از نمایه‌سازی به هر تکه یک جملهٔ زمینه اضافه کنیم؟
