@intro
This edition teaches the same skills as [Building with the Claude API](page:building-with-the-claude-api), but **through Amazon Bedrock**, AWS's managed AI service. The ideas (prompting, evals, tools, RAG, MCP, agents) are identical; what changes is **how you connect**: AWS credentials and IAM instead of an Anthropic API key, Bedrock **model IDs** and **inference profiles**, and the boto3 **Converse API** message format.

**How to read this page:** lessons that are AWS-specific (setup, requests, streaming, the Converse tool format, reranking, contextual retrieval, Claude Code on Bedrock, computer use) are explained in full. Lessons that are the same as the API course are marked **"Same as API course"**, summarized in a few lines, and linked to the full lesson.
~~
این نسخه همان مهارت‌های دورهٔ [ساختن با Claude API](page:building-with-the-claude-api) را یاد می‌دهد، ولی **از طریق Amazon Bedrock**؛ سرویس مدیریت‌شدهٔ هوش مصنوعی AWS. ایده‌ها (پرامپت، ارزیابی، ابزار، RAG، MCP، ایجنت) یکسان‌اند؛ چیزی که عوض می‌شود **روش وصل شدن** است: اعتبارنامه‌های AWS و IAM به جای کلید API آنتروپیک، **شناسهٔ مدل‌ها** و **پروفایل‌های استنتاج** Bedrock و قالب پیام **Converse API** در boto3.

**این صفحه را چطور بخوانی:** درس‌هایی که مخصوص AWS هستند (راه‌اندازی، درخواست، استریم، قالب ابزار در Converse، رتبه‌بندی دوباره، بازیابی زمینه‌دار، Claude Code روی Bedrock، استفاده از کامپیوتر) کامل توضیح داده شده‌اند. درس‌هایی که با دورهٔ API یکی‌اند با **«مشترک با دورهٔ API»** علامت خورده‌اند، در چند خط خلاصه شده‌اند و به درس کامل پیوند دارند.

@lesson
id: overview-of-claude-models
en: Overview of Claude models
fa: مروری بر مدل‌های Claude
url: https://academy.claude.com/courses/claude-with-amazon-bedrock

#explain
Claude comes in families that trade **intelligence, speed and cost**: **Opus** (most capable for complex, long-running work), **Sonnet** (balanced, great for high-volume production) and **Haiku** (fastest and cheapest, ideal for simple, high-volume tasks like classification or routing). The course's examples use **Claude Haiku 4.5** because it's fast and inexpensive while you learn. On Bedrock you must first **enable access** to each model you want in the Bedrock console, in your chosen region.
~~
Claude در خانواده‌هایی می‌آید که بین **هوش، سرعت و هزینه** تعادل برقرار می‌کنند: **Opus** (تواناترین برای کارهای پیچیده و طولانی)، **Sonnet** (متعادل؛ عالی برای محصولات پرحجم) و **Haiku** (سریع‌ترین و ارزان‌ترین؛ ایدئال برای کارهای ساده و پرحجم مثل دسته‌بندی یا مسیریابی). مثال‌های دوره از **Claude Haiku 4.5** استفاده می‌کنند چون موقع یادگیری سریع و ارزان است. روی Bedrock اول باید در کنسول Bedrock و در منطقهٔ انتخابی‌ات، **دسترسی به هر مدلی را که می‌خواهی فعال کنی**.

#analogy
Choosing a model is like choosing a **vehicle**: a sports car (Opus) for the hardest roads, a reliable sedan (Sonnet) for daily commuting, a scooter (Haiku) for quick trips around the block.
~~
انتخاب مدل مثل انتخاب **وسیلهٔ نقلیه** است: یک ماشین اسپرت (Opus) برای سخت‌ترین جاده‌ها، یک سدان مطمئن (Sonnet) برای رفت‌وآمد روزانه، یک اسکوتر (Haiku) برای رفتن سریع تا سر کوچه.

#tip
Newer models (like Claude Opus 5.5) also exist on Bedrock. Check the Bedrock model catalog for which models and features each region and integration offers before you design around one.
~~
مدل‌های جدیدتر (مثل Claude Opus 5.5) هم روی Bedrock هستند. قبل از این‌که طراحی‌ات را به یک مدل گره بزنی، در فهرست مدل‌های Bedrock ببین هر منطقه و هر روش اتصال کدام مدل‌ها و قابلیت‌ها را ارائه می‌دهد.

@section Working with the API | کار با API

@lesson
id: accessing-the-api
en: Accessing the API
fa: دسترسی به API
url: https://academy.claude.com/courses/claude-with-amazon-bedrock/accessing-the-api

#explain
The request flow is the same as with Anthropic's API (your app → your server → Bedrock → Claude), but security is **AWS-native**. You need:

- an **AWS account** with Bedrock enabled in a region where Claude is available;
- **model access** granted for the Claude models you'll use;
- **IAM permissions** for your user or role (for example `bedrock:InvokeModel` and `bedrock:InvokeModelWithResponseStream`, which also cover the Converse API);
- AWS **credentials** that boto3 can find (environment variables, `~/.aws/credentials`, or an IAM role when running on AWS).

There's no Anthropic API key at all: access is controlled by IAM, and usage is billed to your AWS account.
~~
جریان درخواست همان جریان API آنتروپیک است (اپ تو ← سرور تو ← Bedrock ← Claude)، ولی امنیت **بومیِ AWS** است. این‌ها را لازم داری:

- یک **حساب AWS** که Bedrock در منطقه‌ای که Claude در دسترس است فعال باشد؛
- **دسترسی مدل** برای مدل‌های Claude که استفاده می‌کنی؛
- **مجوزهای IAM** برای کاربر یا نقش تو (مثلاً `bedrock:InvokeModel` و `bedrock:InvokeModelWithResponseStream` که Converse API را هم پوشش می‌دهند)؛
- **اعتبارنامه‌های** AWS که boto3 بتواند پیدایشان کند (متغیرهای محیطی، `~/.aws/credentials` یا یک نقش IAM وقتی روی AWS اجرا می‌شوی).

اصلاً کلید API آنتروپیک وجود ندارد: دسترسی با IAM کنترل می‌شود و هزینه به حساب AWS تو نوشته می‌شود.

#code bash Setup
pip install boto3
aws configure          # or use SSO / environment variables / an IAM role
aws bedrock list-foundation-models --by-provider anthropic --region us-west-2 \
    --query "modelSummaries[].modelId"
#end

#warn
Give your app's IAM role **only** the Bedrock actions and models it needs (least privilege), never your personal admin credentials.
~~
به نقش IAM اپت **فقط** همان کارها و مدل‌های Bedrock را بده که لازم دارد (کمترین دسترسی)، هرگز اعتبارنامه‌های مدیر شخصی خودت را.

#analogy
IAM is the **building's badge system**: instead of one master key (an API key), each person's badge opens only the doors they need.
~~
IAM مثل **سیستم کارت ورود یک ساختمان** است: به جای یک شاه‌کلید (کلید API)، کارت هر نفر فقط درهایی را باز می‌کند که لازم دارد.

#terms
IAM = مدیریت هویت و دسترسی = سیستم AWS برای تعریف این‌که چه کسی به چه منبعی و با چه مجوزی دسترسی دارد.

@lesson
id: making-a-request
en: Making a request
fa: فرستادن یک درخواست
url: https://academy.claude.com/courses/claude-with-amazon-bedrock/making-a-request

#explain
The course uses boto3's `bedrock-runtime` client and the **Converse API**: a model ID, a list of messages, and an inference config. Two Bedrock details:

- **Message content is a list of blocks**, even for plain text: `[{"text": "..."}]`.
- **Inference profiles** route your request to a region where the model is hosted. Their IDs add a geographic prefix to the model ID (for example `us.` or `global.`), which also helps with capacity.
~~
دوره از کلاینت `bedrock-runtime` در boto3 و **Converse API** استفاده می‌کند: یک شناسهٔ مدل، فهرستی از پیام‌ها و تنظیمات استنتاج. دو جزئیات Bedrock:

- **محتوای پیام فهرستی از بلوک‌هاست**، حتی برای متن ساده: `[{"text": "..."}]`.
- **پروفایل‌های استنتاج (inference profiles)** درخواستت را به منطقه‌ای می‌فرستند که مدل آن‌جا میزبانی می‌شود. شناسه‌شان یک پیشوند جغرافیایی به شناسهٔ مدل اضافه می‌کند (مثلاً `us.` یا `global.`) که به ظرفیت هم کمک می‌کند.

#code python bedrock_request.py
import boto3

client = boto3.client("bedrock-runtime", region_name="us-west-2")
MODEL_ID = "us.anthropic.claude-haiku-4-5-20251001-v1:0"   # cross-region inference profile

response = client.converse(
    modelId=MODEL_ID,
    messages=[{"role": "user", "content": [{"text": "What is quantum computing? One sentence."}]}],
    inferenceConfig={"maxTokens": 300},
)
print(response["output"]["message"]["content"][0]["text"])
print(response["stopReason"], response["usage"])     # e.g. end_turn, {'inputTokens': ..., ...}
#end

#tip
**Cool tip:** for the newest models and API features you can also use Anthropic's own SDK against Bedrock (`pip install "anthropic[bedrock]"`, the `AnthropicBedrockMantle` client, model IDs like `anthropic.claude-opus-5-5`). Then your code looks exactly like the [API course](page:building-with-the-claude-api#making-a-request), with AWS doing the authentication.
~~
**نکتهٔ خفن:** برای جدیدترین مدل‌ها و قابلیت‌های API می‌توانی SDK خود آنتروپیک را هم روی Bedrock به کار ببری (`pip install "anthropic[bedrock]"`، کلاینت `AnthropicBedrockMantle`، شناسه‌هایی مثل `anthropic.claude-opus-5-5`). آن وقت کدت دقیقاً مثل [دورهٔ API](page:building-with-the-claude-api#making-a-request) می‌شود و احراز هویت را AWS انجام می‌دهد.

#code python The same request with the Anthropic SDK on Bedrock
from anthropic import AnthropicBedrockMantle

client = AnthropicBedrockMantle(aws_region="us-west-2")   # uses your AWS credentials
message = client.messages.create(
    model="anthropic.claude-opus-5-5",
    max_tokens=1000,
    messages=[{"role": "user", "content": "What is quantum computing? One sentence."}],
)
print("".join(b.text for b in message.content if b.type == "text"))
#end

#terms
Inference profile = پروفایل استنتاج = شناسه‌ای در Bedrock که درخواست را بین منطقه‌های مختلف AWS که مدل را میزبانی می‌کنند مسیریابی می‌کند.
Converse API = Converse API = رابط یکدست Bedrock برای گفت‌وگو با مدل‌های مختلف با یک قالب پیام مشترک.

@lesson
id: streaming
en: Streaming
fa: استریم پاسخ
url: https://academy.claude.com/courses/claude-with-amazon-bedrock/streaming

#explain
`converse_stream` returns an event stream. Text arrives in `contentBlockDelta` events; `messageStop` tells you why generation ended, and a final `metadata` event carries token usage. Print deltas as they arrive for a responsive UI.
~~
`converse_stream` یک جریان رویداد برمی‌گرداند. متن در رویدادهای `contentBlockDelta` می‌رسد؛ `messageStop` می‌گوید چرا تولید تمام شد و یک رویداد `metadata` در پایان، مصرف توکن را می‌آورد. برای رابط کاربری پاسخ‌گو، تکه‌ها را همان لحظهٔ رسیدن چاپ کن.

#code python bedrock_stream.py
response = client.converse_stream(
    modelId=MODEL_ID,
    messages=[{"role": "user", "content": [{"text": "Write a 3-line poem about the sea."}]}],
    inferenceConfig={"maxTokens": 300},
)
for event in response["stream"]:
    if "contentBlockDelta" in event:
        print(event["contentBlockDelta"]["delta"].get("text", ""), end="", flush=True)
    elif "messageStop" in event:
        print("\nstop:", event["messageStop"]["stopReason"])
    elif "metadata" in event:
        print("usage:", event["metadata"]["usage"])
#end

#analogy
Same as the API course: a **phone call** instead of waiting for a **letter**.
~~
مثل دورهٔ API: **تماس تلفنی** به جای منتظر ماندن برای **نامه**.

@lesson
id: controlling-model-output
en: Controlling model output
fa: کنترل خروجی مدل
url: https://academy.claude.com/courses/claude-with-amazon-bedrock/controlling-model-output

#explain
Two classic levers for shaping output:

- **Prefilling**: end the messages with a partial assistant turn so Claude continues from your words (for example, forcing it to start with a specific opinion or format).
- **Stop sequences**: strings that end generation immediately, set in `inferenceConfig={"stopSequences": [...]}`.

**What changed:** prefill is rejected by the newest Claude models (use structured outputs or a clear instruction instead); stop sequences still work everywhere.
~~
دو اهرم کلاسیک برای شکل دادن به خروجی:

- **پیش‌پر کردن**: پیام‌ها را با یک نوبت ناتمام دستیار تمام کن تا Claude از کلمه‌های تو ادامه بدهد (مثلاً مجبورش کنی با یک نظر یا قالب خاص شروع کند).
- **دنباله‌های توقف**: رشته‌هایی که تولید را فوراً تمام می‌کنند و در `inferenceConfig={"stopSequences": [...]}` تنظیم می‌شوند.

**چه چیزی عوض شده:** جدیدترین مدل‌های Claude پیش‌پر کردن را رد می‌کنند (به جایش از خروجی ساختاریافته یا یک دستور روشن استفاده کن)؛ دنباله‌های توقف همه‌جا کار می‌کنند.

#code python Prefill + stop sequence (works on Haiku 4.5)
response = client.converse(
    modelId=MODEL_ID,
    messages=[
        {"role": "user", "content": [{"text": "Is tea or coffee better? Give a one-line verdict."}]},
        {"role": "assistant", "content": [{"text": "Coffee is better because"}]},   # prefill
    ],
    inferenceConfig={"maxTokens": 100, "stopSequences": ["\n"]},               # stop at line end
)
print("Coffee is better because" + response["output"]["message"]["content"][0]["text"])
#end

#analogy
Prefill is **starting someone's sentence** for them; a stop sequence is **raising your hand to say "that's enough"**.
~~
پیش‌پر کردن مثل **شروع کردن جملهٔ کسی به جای خودش** است؛ دنبالهٔ توقف مثل **بالا بردن دست برای گفتن «کافی است»**.
