ساختن با API · Build with the API

Claude روی Amazon Bedrock (سرویس هوش مصنوعی AWS)Claude with Amazon Bedrock

65 lessons · 8 quizzes · 8 hr · badge صفحهٔ رسمی در Claude Academy ↗

مناسب برای برنامه‌نویس‌هایی که روی AWS کار می‌کنند، پایتون بلدند و یک حساب AWS با دسترسی به Amazon Bedrock دارند. Developers on AWS who know Python and have an AWS account with Amazon Bedrock access.

۰ از ۶۹ خوانده شده

This edition teaches the same skills as Building with the Claude API, but through Amazon Bedrock, AWS's managed AI service. The ideas (prompting, evals, tools, RAG, MCP, agents) are identical; what changes is how you connect: AWS credentials and IAM instead of an Anthropic API key, Bedrock model IDs and inference profiles, and the boto3 Converse API message format.

How to read this page: lessons that are AWS-specific (setup, requests, streaming, the Converse tool format, reranking, contextual retrieval, Claude Code on Bedrock, computer use) are explained in full. Lessons that are the same as the API course are marked "Same as API course", summarized in a few lines, and linked to the full lesson.

این نسخه همان مهارت‌های دورهٔ ساختن با Claude API را یاد می‌دهد، ولی از طریق Amazon Bedrock؛ سرویس مدیریت‌شدهٔ هوش مصنوعی AWS. ایده‌ها (پرامپت، ارزیابی، ابزار، RAG، MCP، ایجنت) یکسان‌اند؛ چیزی که عوض می‌شود روش وصل شدن است: اعتبارنامه‌های AWS و IAM به جای کلید API آنتروپیک، شناسهٔ مدل‌ها و پروفایل‌های استنتاج Bedrock و قالب پیام Converse API در boto3.

این صفحه را چطور بخوانی: درس‌هایی که مخصوص AWS هستند (راه‌اندازی، درخواست، استریم، قالب ابزار در Converse، رتبه‌بندی دوباره، بازیابی زمینه‌دار، Claude Code روی Bedrock، استفاده از کامپیوتر) کامل توضیح داده شده‌اند. درس‌هایی که با دورهٔ API یکی‌اند با «مشترک با دورهٔ API» علامت خورده‌اند، در چند خط خلاصه شده‌اند و به درس کامل پیوند دارند.

۱

درس ۱ · Lesson 1

مروری بر مدل‌های ClaudeOverview of Claude models

صفحهٔ رسمی ↗

Claude comes in families that trade intelligence, speed and cost: Opus (most capable for complex, long-running work), Sonnet (balanced, great for high-volume production) and Haiku (fastest and cheapest, ideal for simple, high-volume tasks like classification or routing). The course's examples use Claude Haiku 4.5 because it's fast and inexpensive while you learn. On Bedrock you must first enable access to each model you want in the Bedrock console, in your chosen region.

Claude در خانواده‌هایی می‌آید که بین هوش، سرعت و هزینه تعادل برقرار می‌کنند: Opus (تواناترین برای کارهای پیچیده و طولانی)، Sonnet (متعادل؛ عالی برای محصولات پرحجم) و Haiku (سریع‌ترین و ارزان‌ترین؛ ایدئال برای کارهای ساده و پرحجم مثل دسته‌بندی یا مسیریابی). مثال‌های دوره از Claude Haiku 4.5 استفاده می‌کنند چون موقع یادگیری سریع و ارزان است. روی Bedrock اول باید در کنسول Bedrock و در منطقهٔ انتخابی‌ات، دسترسی به هر مدلی را که می‌خواهی فعال کنی.

Think of it like thisمثل این است که…

Choosing a model is like choosing a vehicle: a sports car (Opus) for the hardest roads, a reliable sedan (Sonnet) for daily commuting, a scooter (Haiku) for quick trips around the block.

انتخاب مدل مثل انتخاب وسیلهٔ نقلیه است: یک ماشین اسپرت (Opus) برای سخت‌ترین جاده‌ها، یک سدان مطمئن (Sonnet) برای رفت‌وآمد روزانه، یک اسکوتر (Haiku) برای رفتن سریع تا سر کوچه.

Pro tipنکتهٔ طلایی

Newer models (like Claude Opus 5.5) also exist on Bedrock. Check the Bedrock model catalog for which models and features each region and integration offers before you design around one.

مدل‌های جدیدتر (مثل Claude Opus 5.5) هم روی Bedrock هستند. قبل از این‌که طراحی‌ات را به یک مدل گره بزنی، در فهرست مدل‌های Bedrock ببین هر منطقه و هر روش اتصال کدام مدل‌ها و قابلیت‌ها را ارائه می‌دهد.

درس ۲ · Lesson 2

دسترسی به APIAccessing the API

صفحهٔ رسمی ↗

The request flow is the same as with Anthropic's API (your app → your server → Bedrock → Claude), but security is AWS-native. You need:

  • an AWS account with Bedrock enabled in a region where Claude is available;
  • model access granted for the Claude models you'll use;
  • IAM permissions for your user or role (for example bedrock:InvokeModel and bedrock:InvokeModelWithResponseStream, which also cover the Converse API);
  • AWS credentials that boto3 can find (environment variables, ~/.aws/credentials, or an IAM role when running on AWS).

There's no Anthropic API key at all: access is controlled by IAM, and usage is billed to your AWS account.

جریان درخواست همان جریان API آنتروپیک است (اپ تو ← سرور تو ← Bedrock ← Claude)، ولی امنیت بومیِ AWS است. این‌ها را لازم داری:

  • یک حساب AWS که Bedrock در منطقه‌ای که Claude در دسترس است فعال باشد؛
  • دسترسی مدل برای مدل‌های Claude که استفاده می‌کنی؛
  • مجوزهای IAM برای کاربر یا نقش تو (مثلاً bedrock:InvokeModel و bedrock:InvokeModelWithResponseStream که Converse API را هم پوشش می‌دهند)؛
  • اعتبارنامه‌های AWS که boto3 بتواند پیدایشان کند (متغیرهای محیطی، ~/.aws/credentials یا یک نقش IAM وقتی روی AWS اجرا می‌شوی).

اصلاً کلید API آنتروپیک وجود ندارد: دسترسی با IAM کنترل می‌شود و هزینه به حساب AWS تو نوشته می‌شود.

Watch outحواست باشد

Give your app's IAM role only the Bedrock actions and models it needs (least privilege), never your personal admin credentials.

به نقش IAM اپت فقط همان کارها و مدل‌های Bedrock را بده که لازم دارد (کمترین دسترسی)، هرگز اعتبارنامه‌های مدیر شخصی خودت را.

Think of it like thisمثل این است که…

IAM is the building's badge system: instead of one master key (an API key), each person's badge opens only the doors they need.

IAM مثل سیستم کارت ورود یک ساختمان است: به جای یک شاه‌کلید (کلید API)، کارت هر نفر فقط درهایی را باز می‌کند که لازم دارد.

IAMمدیریت هویت و دسترسی
سیستم AWS برای تعریف این‌که چه کسی به چه منبعی و با چه مجوزی دسترسی دارد.

درس ۳ · Lesson 3

فرستادن یک درخواستMaking a request

صفحهٔ رسمی ↗

The course uses boto3's bedrock-runtime client and the Converse API: a model ID, a list of messages, and an inference config. Two Bedrock details:

  • Message content is a list of blocks, even for plain text: [{"text": "..."}].
  • Inference profiles route your request to a region where the model is hosted. Their IDs add a geographic prefix to the model ID (for example us. or global.), which also helps with capacity.

دوره از کلاینت bedrock-runtime در boto3 و Converse API استفاده می‌کند: یک شناسهٔ مدل، فهرستی از پیام‌ها و تنظیمات استنتاج. دو جزئیات Bedrock:

  • محتوای پیام فهرستی از بلوک‌هاست، حتی برای متن ساده: [{"text": "..."}].
  • پروفایل‌های استنتاج (inference profiles) درخواستت را به منطقه‌ای می‌فرستند که مدل آن‌جا میزبانی می‌شود. شناسه‌شان یک پیشوند جغرافیایی به شناسهٔ مدل اضافه می‌کند (مثلاً us. یا global.) که به ظرفیت هم کمک می‌کند.

Pro tipنکتهٔ طلایی

Cool tip: for the newest models and API features you can also use Anthropic's own SDK against Bedrock (pip install "anthropic[bedrock]", the AnthropicBedrockMantle client, model IDs like anthropic.claude-opus-5-5). Then your code looks exactly like the API course, with AWS doing the authentication.

نکتهٔ خفن: برای جدیدترین مدل‌ها و قابلیت‌های API می‌توانی SDK خود آنتروپیک را هم روی Bedrock به کار ببری (pip install "anthropic[bedrock]"، کلاینت AnthropicBedrockMantle، شناسه‌هایی مثل anthropic.claude-opus-5-5). آن وقت کدت دقیقاً مثل دورهٔ API می‌شود و احراز هویت را AWS انجام می‌دهد.

Inference profileپروفایل استنتاج
شناسه‌ای در Bedrock که درخواست را بین منطقه‌های مختلف AWS که مدل را میزبانی می‌کنند مسیریابی می‌کند.
Converse APIConverse API
رابط یکدست Bedrock برای گفت‌وگو با مدل‌های مختلف با یک قالب پیام مشترک.

گفت‌وگوهای چندنوبتیMulti-turn conversations

صفحهٔ رسمی ↗

Same idea as the API course lesson: Bedrock is stateless too, so you keep the history and resend it. With Converse, append the assistant's response["output"]["message"] as is, then your next {"role": "user", "content": [{"text": ...}]}.

همان ایدهٔ درس دورهٔ API: Bedrock هم بی‌حافظه است؛ پس تاریخچه را نگه می‌داری و دوباره می‌فرستی. با Converse، response["output"]["message"] دستیار را همان‌طور که هست اضافه کن و بعد پیام بعدی‌ات را به شکل {"role": "user", "content": [{"text": ...}]}.

استریم پاسخStreaming

صفحهٔ رسمی ↗

converse_stream returns an event stream. Text arrives in contentBlockDelta events; messageStop tells you why generation ended, and a final metadata event carries token usage. Print deltas as they arrive for a responsive UI.

converse_stream یک جریان رویداد برمی‌گرداند. متن در رویدادهای contentBlockDelta می‌رسد؛ messageStop می‌گوید چرا تولید تمام شد و یک رویداد metadata در پایان، مصرف توکن را می‌آورد. برای رابط کاربری پاسخ‌گو، تکه‌ها را همان لحظهٔ رسیدن چاپ کن.

درس ۸ · Lesson 8

کنترل خروجی مدلControlling model output

صفحهٔ رسمی ↗

Two classic levers for shaping output:

  • Prefilling: end the messages with a partial assistant turn so Claude continues from your words (for example, forcing it to start with a specific opinion or format).
  • Stop sequences: strings that end generation immediately, set in inferenceConfig={"stopSequences": [...]}.

What changed: prefill is rejected by the newest Claude models (use structured outputs or a clear instruction instead); stop sequences still work everywhere.

دو اهرم کلاسیک برای شکل دادن به خروجی:

  • پیش‌پر کردن: پیام‌ها را با یک نوبت ناتمام دستیار تمام کن تا Claude از کلمه‌های تو ادامه بدهد (مثلاً مجبورش کنی با یک نظر یا قالب خاص شروع کند).
  • دنباله‌های توقف: رشته‌هایی که تولید را فوراً تمام می‌کنند و در inferenceConfig={"stopSequences": [...]} تنظیم می‌شوند.

چه چیزی عوض شده: جدیدترین مدل‌های Claude پیش‌پر کردن را رد می‌کنند (به جایش از خروجی ساختاریافته یا یک دستور روشن استفاده کن)؛ دنباله‌های توقف همه‌جا کار می‌کنند.

Think of it like thisمثل این است که…

Prefill is starting someone's sentence for them; a stop sequence is raising your hand to say "that's enough".

پیش‌پر کردن مثل شروع کردن جملهٔ کسی به جای خودش است؛ دنبالهٔ توقف مثل بالا بردن دست برای گفتن «کافی است».

بازیابی زمینه‌دارContextual retrieval

صفحهٔ رسمی ↗

A chunk cut out of a long document often loses its context: "Revenue grew 3% over the previous quarter" (which company? which quarter?). Contextual retrieval fixes this at indexing time: for each chunk, ask Claude to write a short context sentence based on the whole document, prepend it to the chunk, and index the combined text (for both embeddings and BM25). Searches now match on that context too.

تکه‌ای که از یک سند طولانی بریده می‌شود اغلب زمینه‌اش را از دست می‌دهد: «درآمد نسبت به فصل قبل ۳٪ رشد کرد» (کدام شرکت؟ کدام فصل؟). بازیابی زمینه‌دار این را موقع نمایه‌سازی درست می‌کند: برای هر تکه از Claude بخواه بر اساس کل سند یک جملهٔ زمینه کوتاه بنویسد، آن را به اول تکه بچسبان و متن ترکیبی را نمایه کن (هم برای embedding و هم برای BM25). حالا جست‌وجوها روی همان زمینه هم تطبیق پیدا می‌کنند.

Cool tip: the whole document is the same for every chunk, so put it in a cached block (Converse uses a cachePoint block, covered below). You then pay full price for the document once, and a fraction for every other chunk.

نکتهٔ خفن: کل سند برای همهٔ تکه‌ها یکی است؛ پس آن را در یک بلوک کش‌شده بگذار (Converse از بلوک cachePoint استفاده می‌کند که در ادامه می‌آید). آن وقت قیمت کامل سند را فقط یک بار می‌دهی و برای بقیهٔ تکه‌ها بخش کوچکی از آن را.

اجرای موازی Claude CodeParallelizing Claude Code

13 minصفحهٔ رسمی ↗

Running several Claude Code sessions on the same folder makes them trip over each other's edits. The solution: give each instance its own workspace, typically a git worktree (a separate checkout of the same repository on its own branch). Each Claude works in isolation, and you merge the finished branches back. You can even write a custom command that creates the worktree and starts the task for you.

اجرای چند جلسهٔ Claude Code روی یک پوشه باعث می‌شود ویرایش‌هایشان به هم بخورد. راه‌حل: به هر نمونه فضای کاری خودش را بده؛ معمولاً یک git worktree (یک نسخهٔ جدا از همان مخزن روی شاخهٔ خودش). هر Claude جدا کار می‌کند و تو شاخه‌های تمام‌شده را دوباره ادغام می‌کنی. حتی می‌توانی یک فرمان سفارشی بنویسی که worktree را بسازد و کار را برایت شروع کند.

Think of it like thisمثل این است که…

Two chefs can't share one cutting board; give each a station, then plate the dishes together.

دو آشپز نمی‌توانند یک تخته‌برش را با هم استفاده کنند؛ به هر کدام یک ایستگاه بده، بعد غذاها را با هم بچین.

اشکال‌زدایی خودکارAutomated debugging

صفحهٔ رسمی ↗

Claude Code doesn't have to be interactive. In headless mode (claude -p "...") it can run inside scripts and CI: when a test or deployment fails, a job hands Claude the error logs, lets it investigate the code, and produces a proposed fix (as a patch or a pull request) for a human to review. The key is giving it the evidence (logs, failing test output) and a way to verify (rerun the tests).

Claude Code لازم نیست حتماً تعاملی باشد. در حالت بی‌سر (headless) (claude -p "...") می‌تواند داخل اسکریپت‌ها و CI اجرا شود: وقتی یک تست یا استقرار شکست می‌خورد، یک کار خودکار لاگ‌های خطا را به Claude می‌دهد، اجازه می‌دهد کد را بررسی کند و یک اصلاح پیشنهادی (به شکل patch یا pull request) برای بازبینی یک آدم می‌سازد. کلید کار، دادن شواهد (لاگ‌ها، خروجی تست شکست‌خورده) و یک راه راستی‌آزمایی (اجرای دوبارهٔ تست‌ها) است.

Watch outحواست باشد

Keep a human in the loop: let automated fixes arrive as pull requests, never as direct pushes to production branches, and limit which tools the headless run may use.

یک آدم را در حلقه نگه دار: بگذار اصلاح‌های خودکار به شکل pull request برسند، هرگز به شکل push مستقیم روی شاخه‌های اصلی، و محدود کن اجرای بی‌سر از کدام ابزارها استفاده کند.

درس ۶۷ · Lesson 67

استفاده از کامپیوترComputer use

صفحهٔ رسمی ↗

Computer use lets Claude operate a desktop environment: take screenshots, move the mouse, click, type. It's useful for tasks without an API, like automated QA testing of a web app ("sign up, add an item to the cart, check the total") or legacy software. It's slower and less precise than APIs, so use it where nothing better exists, and always in an isolated virtual machine or container.

استفاده از کامپیوتر به Claude اجازه می‌دهد یک محیط دسکتاپ را بچرخاند: اسکرین‌شات بگیرد، ماوس را حرکت دهد، کلیک کند، تایپ کند. برای کارهایی که API ندارند مفید است، مثل آزمون خودکار کیفیت (QA) یک وب‌اپ («ثبت‌نام کن، یک کالا به سبد اضافه کن، جمع را چک کن») یا نرم‌افزارهای قدیمی. از APIها کندتر و کم‌دقت‌تر است؛ پس جایی به کارش ببر که گزینهٔ بهتری نیست، و همیشه در یک ماشین مجازی یا کانتینر ایزوله.

Watch outحواست باشد

Treat everything on screen as untrusted: a web page could contain text that tries to give Claude instructions. Don't give the environment access to sensitive accounts, and require confirmation for consequential actions.

هر چیزی را که روی صفحه است غیرقابل‌اعتماد حساب کن: یک صفحهٔ وب ممکن است متنی داشته باشد که سعی کند به Claude دستور بدهد. به آن محیط دسترسی به حساب‌های حساس نده و برای کارهای پیامددار تأیید بخواه.

Think of it like thisمثل این است که…

Computer use is a remote helper looking at your screen through a video call: capable, but you don't let them near your bank account.

استفاده از کامپیوتر مثل کمک‌کننده‌ای از راه دور است که از طریق تماس تصویری صفحه‌ات را می‌بیند: توانا است، ولی نمی‌گذاری به حساب بانکی‌ات نزدیک شود.

درس ۶۸ · Lesson 68

استفاده از کامپیوتر چطور کار می‌کندHow computer use works

صفحهٔ رسمی ↗

Under the hood it's the same tool-use loop you built earlier. You declare Anthropic's computer-use tool (with the screen size); Claude returns tool_use actions like "screenshot", "left_click at (x, y)" or "type 'hello'"; your code performs them in the virtual desktop and returns a screenshot as the tool result; Claude looks at it and decides the next action. Anthropic provides a reference implementation (a Docker container with a desktop) to start from.

در باطن همان حلقهٔ استفاده از ابزار است که قبلاً ساختی. ابزار computer use آنتروپیک را (با اندازهٔ صفحه) اعلام می‌کنی؛ Claude کارهایی مثل «اسکرین‌شات»، «کلیک چپ روی (x, y)» یا «تایپ 'hello'» را به شکل tool_use برمی‌گرداند؛ کد تو آن‌ها را در دسکتاپ مجازی انجام می‌دهد و یک اسکرین‌شات را به‌عنوان نتیجهٔ ابزار برمی‌گرداند؛ Claude نگاهش می‌کند و کار بعدی را تصمیم می‌گیرد. Anthropic یک پیاده‌سازی مرجع (یک کانتینر Docker با دسکتاپ) برای شروع ارائه می‌دهد.

Step by stepقدم‌به‌قدم

  1. Declare the computer-use tool with the display size.
  2. Claude asks for an action (e.g., take a screenshot).
  3. Your code performs it in the VM.
  4. Return a fresh screenshot as the tool result.
  5. Repeat until the task is done.
  1. ابزار computer use را با اندازهٔ صفحه اعلام کن.
  2. Claude یک کار می‌خواهد (مثلاً گرفتن اسکرین‌شات).
  3. کد تو آن را در ماشین مجازی انجام می‌دهد.
  4. یک اسکرین‌شات تازه را به‌عنوان نتیجهٔ ابزار برگردان.
  5. تا تمام شدن کار تکرار کن.

Pro tipنکتهٔ طلایی

Computer use is still versioned and evolving: the newest models use a newer computer toolset declaration on some platforms (Bedrock still accepts the earlier version for some models). Copy the declaration from the current docs, not from old blog posts.

استفاده از کامپیوتر هنوز نسخه‌دار و در حال تکامل است: جدیدترین مدل‌ها روی بعضی سکوها از اعلان تازه‌تری به اسم toolset استفاده می‌کنند (Bedrock هنوز نسخهٔ قبلی را برای بعضی مدل‌ها می‌پذیرد). اعلان را از مستندات فعلی کپی کن، نه از پست‌های قدیمی وبلاگ‌ها.

  • دادهٔ ساختاریافته: ابزار به‌عنوان اسکیما، یا خروجی ساختاریافته روی مدل‌های جدیدتر.
  • چیزهای اضافهٔ RAG: رتبه‌بندی دوباره با Claude، بازیابی زمینه‌دار (یک جملهٔ زمینه برای هر تکه).
  • کش: {"cachePoint": {"type": "default"}} بعد از بخش ثابت.
  • روی Bedrock نیست: ابزارهای سمت سرور آنتروپیک (جست‌وجوی وب، اجرای کد)، Files API، Message Batches.
  • جدیدترین مدل‌ها و قابلیت‌ها: SDK آنتروپیک با کلاینت AnthropicBedrockMantle و شناسه‌های مدل با پیشوند anthropic..
  • Claude Code: CLAUDE_CODE_USE_BEDROCK=1؛ اجرای موازی با git worktree.

What's the difference between the content of a Converse message and an Anthropic API message?
فرق محتوای یک پیام Converse با یک پیام API آنتروپیک چیست؟
Converse content is always a list of blocks like [{"text": "..."}]; tool blocks are named toolUse / toolResult and tools are wrapped in toolSpec.
محتوای Converse همیشه فهرستی از بلوک‌ها مثل [{"text": "..."}] است؛ بلوک‌های ابزار toolUse / toolResult نام دارند و ابزارها در toolSpec پیچیده می‌شوند.

Why add a context sentence to each chunk before indexing?
چرا قبل از نمایه‌سازی به هر تکه یک جملهٔ زمینه اضافه کنیم؟
Chunks lose their context when cut from a document; the sentence restores it so both semantic and keyword search can match it (contextual retrieval).
تکه‌ها وقتی از سند بریده می‌شوند زمینه‌شان را از دست می‌دهند؛ این جمله آن را برمی‌گرداند تا هم جست‌وجوی معنایی و هم کلیدواژه‌ای بتوانند پیدایش کنند (بازیابی زمینه‌دار).
