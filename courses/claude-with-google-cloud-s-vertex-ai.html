66 lessons · 9 quizzes · 8.5 hr · badge صفحهٔ رسمی در Claude Academy ↗

مناسب برای برنامه‌نویس‌هایی که روی Google Cloud کار می‌کنند، پایتون بلدند و یک پروژهٔ Google Cloud با دسترسی به Vertex AI دارند. Developers on Google Cloud who know Python and have a Google Cloud project with Vertex AI access.

۰ از ۷۶ خوانده شده

This edition teaches the skills of Building with the Claude API on Google Cloud's Vertex AI. The good news: Anthropic's Python SDK has a Vertex client (AnthropicVertex), so after setup your code is almost identical to the API course; you authenticate with Google Cloud credentials instead of an Anthropic API key, and use the model IDs listed in Model Garden.

How to read this page: Vertex-specific lessons (setup, requests, controlling output, the batch tool, tools for structured data, reranking, contextual retrieval) are explained in full; lessons identical to the API course are marked "Same as API course" with a short summary and a link.

این نسخه مهارت‌های دورهٔ ساختن با Claude API را روی Vertex AI در Google Cloud یاد می‌دهد. خبر خوب: SDK پایتون آنتروپیک یک کلاینت Vertex (AnthropicVertex) دارد؛ پس بعد از راه‌اندازی، کدت تقریباً مثل دورهٔ API است؛ فقط به جای کلید API آنتروپیک با اعتبارنامه‌های Google Cloud احراز هویت می‌کنی و از شناسه‌های مدلی که در Model Garden آمده استفاده می‌کنی.

این صفحه را چطور بخوانی: درس‌های مخصوص Vertex (راه‌اندازی، درخواست، کنترل خروجی، ابزار دسته‌ای، ابزار برای دادهٔ ساختاریافته، رتبه‌بندی دوباره، بازیابی زمینه‌دار) کامل توضیح داده شده‌اند؛ درس‌هایی که با دورهٔ API یکی‌اند با «مشترک با دورهٔ API» علامت خورده‌اند و یک خلاصهٔ کوتاه و پیوند دارند.

درس ۲ · Lesson 2

راه‌اندازی Vertex AIVertex AI setup

صفحهٔ رسمی ↗

Four steps before your first request:

  1. In your Google Cloud project, open Model Garden, find the Claude model you want and enable it (accept the terms).
  2. Install the gcloud CLI and log in.
  3. Set up Application Default Credentials so code can authenticate.
  4. Install the SDK with Vertex support. The Anthropic SDK then picks up your credentials automatically.

چهار قدم قبل از اولین درخواست:

  1. در پروژهٔ Google Cloud خودت، Model Garden را باز کن، مدل Claude مورد نظرت را پیدا کن و فعالش کن (شرایط را بپذیر).
  2. gcloud CLI را نصب کن و وارد شو.
  3. اعتبارنامه‌های پیش‌فرض اپلیکیشن (ADC) را راه بینداز تا کد بتواند احراز هویت کند.
  4. SDK را با پشتیبانی Vertex نصب کن. SDK آنتروپیک بعد از آن اعتبارنامه‌هایت را خودکار پیدا می‌کند.

Watch outحواست باشد

In production, don't use your personal login: run your app with a service account that has only the Vertex AI permissions it needs.

در محیط واقعی از ورود شخصی‌ات استفاده نکن: اپت را با یک حساب سرویس (service account) اجرا کن که فقط مجوزهای Vertex AI لازمش را دارد.

فرستادن یک درخواستMaking a request

صفحهٔ رسمی ↗

Create an AnthropicVertex client with your project ID and a region (the global endpoint, or a specific region if you need data to stay there), then call messages.create exactly as in the API course.

یک کلاینت AnthropicVertex با شناسهٔ پروژه و یک منطقه بساز (نقطهٔ global، یا یک منطقهٔ مشخص اگر لازم است داده همان‌جا بماند)، بعد messages.create را دقیقاً مثل دورهٔ API صدا بزن.

Pro tipنکتهٔ طلایی

Model IDs on Vertex can differ from Anthropic's (some older models carry a version suffix such as @20251001). Copy the ID from the model's card in Model Garden.

شناسهٔ مدل‌ها روی Vertex ممکن است با شناسه‌های آنتروپیک فرق کند (بعضی مدل‌های قدیمی‌تر یک پسوند نسخه مثل @20251001 دارند). شناسه را از کارت همان مدل در Model Garden کپی کن.

Think of it like thisمثل این است که…

Same car, different toll pass: the driving (your code) doesn't change; only the way you pay at the gate (authentication) does.

همان ماشین، با کارت عوارض متفاوت: رانندگی (کد تو) عوض نمی‌شود؛ فقط روش پرداخت سر دروازه (احراز هویت) فرق می‌کند.

درس ۸ · Lesson 8

کنترل خروجی مدلControlling model output

صفحهٔ رسمی ↗

Two levers: prefilling the assistant's reply so Claude continues from your words, and stop sequences that end generation at a chosen string. Combined, they extract exactly what you want (for example, just a code block). On the newest models prefill returns a 400, so use structured outputs or explicit instructions there; stop sequences still work on every model.

دو اهرم: پیش‌پر کردن جواب دستیار تا Claude از کلمه‌های تو ادامه بدهد، و دنباله‌های توقف که تولید را سر یک رشتهٔ انتخابی تمام می‌کنند. با هم، دقیقاً همان چیزی را که می‌خواهی بیرون می‌کشند (مثلاً فقط یک بلوک کد). روی جدیدترین مدل‌ها پیش‌پر کردن خطای 400 می‌دهد؛ پس آن‌جا از خروجی ساختاریافته یا دستورهای صریح استفاده کن؛ دنباله‌های توقف روی همهٔ مدل‌ها کار می‌کنند.

Pro tipنکتهٔ طلایی

The modern equivalent for the newest models: ask for the exact format ("Respond with only the command, no explanation") or use structured outputs with a schema like {"command": "string"}.

معادل امروزی برای جدیدترین مدل‌ها: قالب دقیق را بخواه («فقط فرمان را بنویس، بدون توضیح») یا از خروجی ساختاریافته با اسکیمایی مثل {"command": "string"} استفاده کن.

درس ۳۳ · Lesson 33

ابزار دسته‌ایThe batch tool

صفحهٔ رسمی ↗

When Claude makes independent tool calls one per turn, every call costs a full round trip. The batch tool is a wrapper tool whose input is a list of other tool calls, so Claude can request several at once; your code runs them (in parallel if you like) and returns all results together.

وقتی Claude فراخوانی‌های مستقل را هر نوبت یکی انجام می‌دهد، هر فراخوانی یک رفت‌وبرگشت کامل هزینه دارد. ابزار دسته‌ای یک ابزار پوششی است که ورودی‌اش فهرستی از فراخوانی‌های ابزارهای دیگر است؛ پس Claude می‌تواند چند تا را با هم درخواست کند؛ کد تو اجرایشان می‌کند (اگر خواستی موازی) و همهٔ نتیجه‌ها را با هم برمی‌گرداند.

Pro tipنکتهٔ طلایی

Measure before adopting it: current Claude models already issue parallel tool calls on their own fairly often. If yours does, the plain approach is simpler.

قبل از به کار بردنش اندازه بگیر: مدل‌های فعلی Claude همین حالا هم خیلی وقت‌ها خودشان ابزارها را موازی صدا می‌زنند. اگر مدل تو این کار را می‌کند، روش ساده‌تر بهتر است.

۳۴

درس ۳۴ · Lesson 34

ابزار برای دادهٔ ساختاریافتهTools for structured data

صفحهٔ رسمی ↗

Compared with prompt-based methods (prefill and stop sequences), the tool-based approach is more reliable: define a tool whose JSON schema *is* the structure you want, have Claude call it, and read the tool's input as your data. The course forces the call with tool_choice={"type": "tool", "name": ...}; it's more setup, but the output is far more consistent.

Today: on the newest models (Opus 5.5, Sonnet 5.5, Fable 5.1) forced tool_choice returns a 400. Use structured outputs (supported on Vertex) for pure extraction, or auto + strict: true + an explicit instruction when you really want a tool call.

در مقایسه با روش‌های مبتنی بر پرامپت (پیش‌پر کردن و دنبالهٔ توقف)، روش مبتنی بر ابزار مطمئن‌تر است: ابزاری تعریف کن که اسکیمای JSON آن *همان* ساختاری است که می‌خواهی، کاری کن Claude صدایش بزند و ورودی ابزار را به‌عنوان داده‌ات بخوان. دوره فراخوانی را با tool_choice={"type": "tool", "name": ...} اجباری می‌کند؛ راه‌اندازی بیشتری می‌خواهد، ولی خروجی خیلی یکدست‌تر است.

امروز: روی جدیدترین مدل‌ها (Opus 5.5، Sonnet 5.5، Fable 5.1) اجبار tool_choice خطای 400 می‌دهد. برای استخراج خالص از خروجی ساختاریافته (که Vertex پشتیبانی می‌کند) استفاده کن، یا وقتی واقعاً فراخوانی ابزار می‌خواهی، auto + strict: true + یک دستور صریح.

Think of it like thisمثل این است که…

Prompt-based extraction is asking someone to write their details neatly on a blank page; tool-based is handing them a printed form; structured outputs is a form where the pen can't write outside the boxes.

استخراج مبتنی بر پرامپت مثل این است که از کسی بخواهی مشخصاتش را تمیز روی یک برگهٔ سفید بنویسد؛ مبتنی بر ابزار مثل دادن یک فرم چاپی است؛ خروجی ساختاریافته فرمی است که قلم اصلاً نمی‌تواند بیرون خانه‌ها بنویسد.

خلاصهٔ یک‌نگاهCheat sheet

  • Enable Claude in Model Garden; authenticate with gcloud auth application-default login (a service account in production).
  • pip install "anthropic[vertex]" → AnthropicVertex(project_id=..., region="global") → same messages.create as the API course.
  • Copy model IDs from Model Garden (older models may have an @date suffix).
  • Output control: prefill + stop sequences on older models; structured outputs on the newest.
  • Tools: same format as the API course; batch tool for many independent calls; tools for structured data (or structured outputs today).
  • RAG extras: reranking, contextual retrieval (cache the document while contextualizing).
  • Not on Vertex: code execution, Files API, web fetch, MCP connector; web search is the basic version only.
  • Claude Code on Vertex: CLAUDE_CODE_USE_VERTEX=1 + region + project ID.
  • Claude را در Model Garden فعال کن؛ با gcloud auth application-default login احراز هویت کن (در محیط واقعی با یک حساب سرویس).
  • pip install "anthropic[vertex]" ← AnthropicVertex(project_id=..., region="global") ← همان messages.create دورهٔ API.
  • شناسهٔ مدل‌ها را از Model Garden کپی کن (مدل‌های قدیمی‌تر ممکن است پسوند @تاریخ داشته باشند).
  • کنترل خروجی: پیش‌پر کردن + دنبالهٔ توقف روی مدل‌های قدیمی‌تر؛ خروجی ساختاریافته روی جدیدترین‌ها.
  • ابزارها: همان قالب دورهٔ API؛ ابزار دسته‌ای برای فراخوانی‌های مستقل زیاد؛ ابزار برای دادهٔ ساختاریافته (یا امروزه خروجی ساختاریافته).
  • چیزهای اضافهٔ RAG: رتبه‌بندی دوباره، بازیابی زمینه‌دار (موقع زمینه‌دار کردن، سند را کش کن).
  • روی Vertex نیست: اجرای کد، Files API، web fetch، MCP connector؛ جست‌وجوی وب فقط نسخهٔ پایه.
  • Claude Code روی Vertex: CLAUDE_CODE_USE_VERTEX=1 + منطقه + شناسهٔ پروژه.
